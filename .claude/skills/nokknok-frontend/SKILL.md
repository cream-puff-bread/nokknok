# 넉넉 프론트엔드 개발 규칙

## 화면 구성

- 가용잔고 대시보드: 실제 사용 가능한 금액과 확정 지출 내역, 미사용 의심 구독 표시
- 시뮬레이션 입력: 자연어 질의 입력과 결과 대기 상태
- 잔고 추이 차트: 6개월 예측을 세 가지 시나리오 밴드로 표시
- 결제 라우팅 결과: 추천 카드, 시점, 할부 조건과 근거 약관
- 페르소나 선택 및 파일 업로드

## 절대 규칙

### 타입 정의를 따른다

`references/types.ts`에 정의된 타입을 그대로 사용한다. API 응답 구조를 임의로 가정하지 않는다. 필요한 필드가 없다면 화면에서 만들어내는 대신 그 사실을 알린다.

### 금액 계산을 프론트에서 하지 않는다

할인액, 잔고, 실적 충족 여부는 모두 백엔드가 계산한 값을 받아 표시만 한다. 프론트에서 재계산하면 백엔드와 값이 어긋난다. 단위 변환(원 단위 콤마 표기 등)만 허용한다.

### 브라우저 저장소를 사용하지 않는다

localStorage와 sessionStorage를 쓰지 않는다. 상태는 React 상태로 관리한다.

## 스타일 기준

- Tailwind CSS를 사용한다. 별도 CSS 파일을 만들지 않는다.
- 색상, 간격, 폰트 크기는 공통 규칙을 따른다. 임의의 값을 쓰지 않는다.
- 금액은 세 자리 콤마와 '원' 단위로 표기한다.
- 시나리오 명칭은 화면에서 '여유', '보통', '빠듯'으로 표기한다. 낙관, 기본, 비관은 내부 용어이므로 화면에 노출하지 않는다.

## 컴포넌트 작성 기준

- 공통 컴포넌트(버튼, 카드, 입력, 로딩)를 먼저 확인하고 재사용한다. 비슷한 것을 새로 만들지 않는다.
- 하나의 컴포넌트는 하나의 역할만 한다. 데이터 조회와 표시를 한 컴포넌트에 섞지 않는다.
- 컴포넌트 파일은 200줄을 넘기지 않는다. 넘으면 분리한다.

## 상태 처리

모든 비동기 화면은 세 가지 상태를 반드시 처리한다.

- 로딩 중: 스켈레톤 또는 스피너
- 오류: 사용자가 이해할 수 있는 메시지와 재시도 수단
- 빈 상태: 데이터가 없을 때 안내 문구

특히 LLM 응답은 수 초가 걸리므로 로딩 상태를 반드시 표시한다. 화면이 멈춘 것처럼 보이면 시연에서 문제가 된다.

## 차트

- Recharts를 사용한다.
- 세 가지 시나리오는 밴드 형태로 겹쳐 표시하고, 기본 시나리오를 진하게 강조한다.
- 잔고가 마이너스로 전환되는 지점은 시각적으로 구분되게 표시한다.
- 축 단위는 만원 단위로 축약해 표시한다.

## 커밋

Conventional Commits 형식을 따른다.

```
feat: 잔고 추이 차트 시나리오 밴드 추가
fix: 금액 표기 콤마 누락 수정
style: 대시보드 카드 간격 조정
```

## 작성하지 않는 것

- 인증, 회원가입 화면 (MVP 범위 밖)
- 설정 페이지
- 다국어 처리
- 다크모드 (시간이 남을 때만)
